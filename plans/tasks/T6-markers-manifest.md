# T6 — Markers and manifest store

Parent plan: [`plans/readme-generation.md`](../readme-generation.md) (sections "Decisions", "Mode resolution", "Pipeline" steps 1 and 8, "Project structure").
Depends on: T1 (`core/models/manifest.py`, `core/errors.py`). Consumed by: T2 (`resolve_mode`), T18 (preflight), and the commit stage (writes the manifest and marker).

## 1. Goal

Provide the deterministic, I/O-light persistence layer for ownership:
- render, parse and strip the README marker `<!-- generated by readme-stack vN -->`;
- load, validate, canonicalize and save `<docs-dir>/.readme-stack.json` with byte-stable output;
- hash generated files so hand edits can be detected;
- build a `DocsState` snapshot (README, marker, manifest status, per-file hash status, docs dir existence) that `resolve_mode` and preflight read.

Loading never crashes on bad input. Invalid JSON, a schema violation, a foreign `tool` value or an unsafe path comes back as `ManifestStatus.INVALID` with a message. The only exceptions raised are programming errors (bad arguments).

### `core/models/docs_state.py`
```python
from dataclasses import dataclass, field
from enum import StrEnum
from collections.abc import Mapping

from readme_stack.core.models.manifest import Manifest


class ManifestStatus(StrEnum):
    ABSENT = "absent"      # manifest file does not exist
    INVALID = "invalid"    # unreadable, bad JSON, schema/semantic violation, foreign tool
    VALID = "valid"        # parsed, format_version == current
    OLDER = "older"        # tool == readme-stack, format_version < current (not parsed further)
    NEWER = "newer"        # tool == readme-stack, format_version > current (not parsed further)


class FileStatus(StrEnum):
    CLEAN = "clean"              # file exists, normalized sha256 == manifest sha256
    HAND_EDITED = "hand_edited"  # exists but hash differs, or is not a regular file / is a symlink
    MISSING = "missing"          # path does not exist


class VersionCmp(StrEnum):
    OLDER = "older"
    CURRENT = "current"
    NEWER = "newer"


@dataclass(frozen=True, slots=True)
class DocsState:
    readme_path: str                      # POSIX, relative to repo root, e.g. "README.md"
    readme_exists: bool                   # regular file at readme_path
    readme_marker_version: int | None     # N from the marker, None if no marker
    docs_dir: str                         # POSIX, relative to repo root, e.g. "docs/architecture"
    docs_dir_exists: bool                 # anything exists at docs_dir (dir or file)
    manifest_path: str                    # f"{docs_dir}/.readme-stack.json"
    manifest_status: ManifestStatus
    manifest: Manifest | None = None      # set only when manifest_status == VALID
    manifest_format_version: int | None = None  # raw value when readable (VALID/OLDER/NEWER)
    manifest_error: str | None = None     # human-readable reason when INVALID
    file_statuses: Mapping[str, FileStatus] = field(default_factory=dict)
    # ^ manifest entry path -> status; populated only when VALID; keys in sorted order

    @property
    def marker_present(self) -> bool: ...          # readme_marker_version is not None
    @property
    def is_our_format(self) -> bool: ...           # marker_present and manifest_status == VALID
    @property
    def hand_edited_paths(self) -> tuple[str, ...]: ...  # sorted
    @property
    def missing_paths(self) -> tuple[str, ...]: ...      # sorted
```

## 4. Detailed behavior and edge cases

### 4.1 Marker
- **Placement:** the marker is the first line of README.md, followed by one blank line, then the body. We write it and it is invisible when rendered. Putting it first means a single-line check, and a README that merely quotes or documents the marker (for example this project's own README) is not mistaken for ours.
- **Rendered form:** exactly `<!-- generated by readme-stack v{N} -->`, where N = `MANIFEST_FORMAT_VERSION`.
- **Regex** (applied to a single line, CR already removed):
  ```python
  MARKER_RE = re.compile(
      r"^[ \t]*<!--[ \t]*generated by readme-stack v(?P<version>[1-9][0-9]{0,5})[ \t]*-->[ \t]*$"
  )
  ```
  Case-sensitive. No leading zeros, `v0` rejected, capped at 6 digits. Extra text inside the comment means no match.
- **find_marker tolerance:** remove one leading U+FEFF (BOM). Split lines on `\r\n`, `\r` or `\n` with `re.split(r"\r\n|\r|\n", text)`, not `str.splitlines`, which also splits on `\x0c` and `\u2028`. Skip leading lines that contain only whitespace, then test only the **first non-blank line**. A marker further down returns None. Empty text returns None.
- **strip_marker(text):** remove the BOM. If `find_marker` matches, drop the blank lines before the marker, the marker line itself, and **at most one** blank line after it. The original line endings of the remaining text are kept. Without a marker, return the text with only the BOM removed.
- **apply_marker(body, v):** `render_marker(v) + "\n\n" + strip_marker(body)`. This is idempotent (`apply_marker(apply_marker(b)) == apply_marker(b)`) and replaces an old-version marker. Assemble (a later task) normalizes line endings to LF before this call. apply_marker does not convert CRLF.
- **Round-trip guarantee:** `parse_marker(apply_marker(b, v)) == v`. `strip_marker(apply_marker(b, v)) == strip_marker(b)`, which equals `b` when `b` has no BOM and no marker.

### 4.2 Hashing
- `normalize_for_hash`: remove one leading UTF-8 BOM (`b"\xef\xbb\xbf"`), then replace `b"\r\n"` with `b"\n"`. A lone `\r` is left alone. No trailing-whitespace or final-newline normalization, because those are real edits.
- **Why normalize:** a Windows checkout with `core.autocrlf=true`, or an editor that adds a BOM, would otherwise flag every generated file as hand-edited, and the user would have to pass `--force` for nothing. A CRLF-only change carries no meaningful edit.
- The hash covers the **full file as written, including the README marker**. The commit stage must compute `sha256 = hash_text(final_content)` from exactly the string it writes (UTF-8, LF). Document this in the `hash_text` docstring.
- `hash_file` reads bytes (`Path.read_bytes`), so decoding never fails.

### 4.3 Manifest JSON format
- `render_manifest`:
  1. canonicalize (below);
  2. `manifest.model_dump(mode="json")`;
  3. `json.dumps(data, indent=2, sort_keys=True, ensure_ascii=False) + "\n"`.

  The result has LF line endings, a single trailing newline, no timestamps and no volatile fields, so the same `Manifest` always produces the same bytes.
- `canonicalize_manifest`: order `files` by `path`. Sort `source_paths` and remove duplicates within each entry (glob order has no meaning). Normalize `docs_dir` and every entry path with `normalize_rel_path`. The result is returned with `model_copy(update=...)`. The input is not mutated.
- `save_manifest`:
  - Raises `ValueError` if `manifest.format_version != MANIFEST_FORMAT_VERSION` or if `manifest.tool` is not `"readme-stack"`, because we only ever write the current format.
  - Writes the file atomically: `tempfile.NamedTemporaryFile(dir=target.parent, delete=False)`, write UTF-8 bytes, `flush`, `os.fsync`, then `os.replace`. The temp file is removed on failure.
  - Creates the parent directory (`mkdir(parents=True, exist_ok=True)`).
  - `OSError` propagates, and the workflow maps it to exit 1.
  - The commit stage calls this last. The ChangeSet (another task) may reuse `render_manifest` for dry-run diffs.

### 4.4 Loading and validation (`parse_manifest`, the pure core of `load_manifest`)
The steps run in order. The first failure returns INVALID with a one-line `error`.
1. If `len(raw) > MAX_MANIFEST_BYTES`: INVALID ("manifest too large").
2. Decode with `raw.decode("utf-8-sig")` (a BOM is tolerated). A `UnicodeDecodeError` is INVALID.
3. `json.loads(text, object_pairs_hook=_reject_duplicate_keys)`. A `JSONDecodeError`, a duplicate key (`ValueError`) or a `RecursionError` is INVALID.
4. The top level must be a `dict`, otherwise INVALID.
5. `tool` must equal `"readme-stack"`, otherwise INVALID ("not a readme-stack manifest").
6. `format_version` must be an `int` and not a `bool`, and `>= 1`, otherwise INVALID.
7. `compare_format_version`:
   - NEWER: return `ManifestLoad(NEWER, format_version=v)` without further validation, because the schema is unknown.
   - OLDER: return `ManifestLoad(OLDER, format_version=v)` without further validation. There is no migration, and T2 maps OLDER to RECREATE.
8. `Manifest.model_validate(data)`. A `ValidationError` is INVALID, with the first 3 errors formatted as `loc: msg`.
9. Semantic checks (T6-owned, so T1 models stay simple):
   - every `files[].path` passes `normalize_rel_path` and is unchanged by it;
   - each path is either the README path (`"README.md"`) or lies under `docs_dir + "/"`;
   - no duplicate `path` and no duplicate `page_id`;
   - `manifest.docs_dir` (normalized) equals the `docs_dir` argument (normalized). A mismatch is INVALID ("manifest docs_dir 'x' does not match --docs-dir 'y'"; see open question 3);
   - the manifest's own path is not listed in `files`.
10. Success returns `ManifestLoad(VALID, manifest, format_version=v)`.

`load_manifest(repo_root, docs_dir)` reads `repo_root / manifest_path_for(docs_dir)`:
- `FileNotFoundError` or `NotADirectoryError` gives ABSENT;
- a path that exists but is not a regular file (for example a directory) is INVALID;
- any other `OSError` (for example `PermissionError`) is INVALID with the error message;
- otherwise the bytes go to `parse_manifest`.

### 4.5 Path normalization
- Every path stored or compared is **POSIX, relative to the repo root** (not to docs_dir). Examples: `README.md`, `docs/architecture/cli.md`.
- `normalize_rel_path(p)`:
  - reject an empty string, a string containing `\x00`, or a string containing `\` (Windows separators are not accepted in the manifest; the caller converts CLI input first);
  - reject absolute paths: a leading `/` or a drive letter (`PurePosixPath(p).is_absolute()` or `PureWindowsPath(p).drive`);
  - collapse `.` segments and duplicate slashes with `PurePosixPath`. Any `..` segment is rejected, even when it would resolve inside the repo;
  - reject a result of `.`;
  - return `str(PurePosixPath(...))`, which has no trailing slash.

  Failures raise `ValueError`. Inside `parse_manifest` they become INVALID.
- `source_paths` are globs. They are only checked for being relative (no leading `/`, no `..` segment), not normalized, because glob matching belongs to the impact task.

### 4.6 File status (`file_status`)
For `target = repo_root / entry.path`:
- `os.lstat` raises `FileNotFoundError` or `NotADirectoryError`: MISSING.
- It is a symlink or not a regular file: HAND_EDITED. We never follow symlinks, so we never escape the repo or treat foreign content as ours.
- `hash_file(target) == entry.sha256`: CLEAN.
- Otherwise HAND_EDITED.
- An `OSError` while reading (for example permissions) counts as HAND_EDITED, the conservative choice that preserves the file. It is logged at debug level through `logging.getLogger(__name__)`.

### 4.7 `load_docs_state`
1. Normalize `readme_path` and `docs_dir` with `normalize_rel_path`. A `ValueError` propagates as a programming error, because the CLI validates `--docs-dir` first.
2. README:
   - `readme_exists` is True for a regular file that is not a symlink (`lstat`).
   - If it exists, read the bytes, decode with `utf-8` and `errors="replace"`, and set `readme_marker_version = parse_marker(text)`.
   - An `OSError` on read means `readme_exists=True` and `readme_marker_version=None`, so the README is treated as foreign.
3. `docs_dir_exists = os.path.lexists(repo_root / docs_dir)`.
4. `load_manifest(...)`.
5. If VALID, `file_statuses = {e.path: file_status(repo_root, e) for e in sorted(files, key=path)}`. Otherwise `{}`.
6. Return `DocsState(...)`. It performs no git calls: tracked/clean state for a foreign README belongs to preflight (T18) through the Git port.

### 4.8 Where DocsState lives, and why
The **types** (`DocsState`, `ManifestStatus`, `FileStatus`, `VersionCmp`) live in `core/models/docs_state.py`. The **loader** (`load_docs_state`) lives in `publishing/manifest_store.py`.
- The layering rule is `publishing → core` only. `core/modes.resolve_mode` (T2) must accept a DocsState, so the type cannot live in publishing without core importing outward.
- Keeping the dataclass in core lets T2 build DocsState values directly in table tests without touching the filesystem.
- It is a frozen stdlib dataclass rather than pydantic because it is an internal value object and is never serialized.

## 6. Test plan

Tests use pytest with `tmp_path`, and no git or network. Helper: `make_manifest(**overrides)` builds a valid `Manifest` with README plus two pages.

**Markers (`test_markers.py`)**
1. `render_marker(1) == "<!-- generated by readme-stack v1 -->"`. `render_marker(0)` raises `ValueError`.
2. Round-trip: `parse_marker(apply_marker(body, v)) == v` for v in {1, 2, 42}.
3. `strip_marker(apply_marker(body)) == body` for a body without a marker.
4. `apply_marker` is idempotent and replaces an existing `v1` marker with `v2`, leaving a single marker line.
5. Tolerance (parametrized), all parse to 1:
   - leading BOM;
   - CRLF endings;
   - lone CR endings;
   - spaces or tabs around and inside the comment (`<!--   generated by readme-stack v1   -->`);
   - leading blank or whitespace-only lines.
6. Rejections (parametrized), all return None:
   - marker on line 3 after a heading;
   - `v0`, `v01`, `vX`;
   - uppercase `Generated By`;
   - extra text inside the comment;
   - text after `-->` other than whitespace;
   - empty string;
   - README describing the marker inside a code block.
7. `strip_marker` removes at most one blank line after the marker, and preserves the CRLF endings of the rest of the text.
8. `strip_marker` on text without a marker returns the text with only the BOM removed.

**Hashing and paths (`test_manifest_store.py`)**

9. `hash_bytes(b"a\r\nb") == hash_bytes(b"a\nb") == hash_bytes(b"\xef\xbb\xbfa\nb")`. `hash_bytes(b"a\rb") != hash_bytes(b"a\nb")`.
10. `hash_bytes(b"a\n") != hash_bytes(b"a")`: the trailing newline counts.
11. `hash_text(s) == hash_file(p)` after `p.write_text(s)` with LF. The known digest of `b""` is `e3b0c442…b855`.
12. `normalize_rel_path`:
    - accepted: `"docs//a/./b.md"` gives `"docs/a/b.md"`;
    - rejected: `/abs`, `C:/x`, `a\\b`, `../x`, `a/../b`, `.`, `""`.

**Manifest render/load**

13. Byte stability: two `render_manifest` calls, and render after building entries in shuffled order, produce identical strings. The output ends with exactly one `\n`, has no `\r`, has sorted keys, uses 2-space indent, and non-ASCII titles appear unescaped.
14. Golden file: `render_manifest(make_manifest())` equals an inline expected string (this pins the format).
15. Round trip: `save_manifest` then `load_manifest` gives VALID, and the loaded manifest equals `canonicalize_manifest(original)`. Re-saving produces identical bytes.
16. `save_manifest` creates the missing docs dir, leaves no temp files behind, and raises `ValueError` when `format_version != MANIFEST_FORMAT_VERSION`.
17. ABSENT when the manifest file does not exist, and also when the docs dir does not exist.
18. INVALID (parametrized; each asserts status, a non-empty `error`, and no exception):
    - `b"{"`;
    - `b"[]"`;
    - `b"null"`;
    - non-UTF-8 bytes;
    - duplicate key;
    - `tool: "other"`;
    - `format_version` missing, `"1"`, `true`, or `0`;
    - missing `files`;
    - an extra unknown field;
    - a bad sha256 (uppercase or short);
    - duplicate path;
    - duplicate page_id;
    - an entry path outside docs_dir (not README);
    - an entry path with `..`;
    - an absolute entry path;
    - a `docs_dir` mismatch;
    - oversize input (monkeypatch `MAX_MANIFEST_BYTES` small);
    - the manifest path is a directory.
19. NEWER: `{"tool": "readme-stack", "format_version": 2, ...garbage}` with `MANIFEST_FORMAT_VERSION == 1` gives NEWER with `format_version=2` and `manifest=None`, even though the rest of the schema is invalid.
20. OLDER: monkeypatch the current version to 2 and a v1 manifest gives OLDER with `format_version=1`.
21. BOM-prefixed manifest bytes load as VALID.

**File status and DocsState**

22. After writing all files with contents matching their hashes, every status is CLEAN.
23. After an edit to one page, that page is HAND_EDITED and the others stay CLEAN. `hand_edited_paths` returns that page.
24. Converting a clean file to CRLF, or adding a BOM, keeps it CLEAN.
25. Deleting one page makes it MISSING, and `missing_paths` returns it.
26. Replacing a page with a symlink to identical content makes it HAND_EDITED. Replacing a page with a directory makes it HAND_EDITED.
27. Editing the README body gives HAND_EDITED for `README.md`.
28. `load_docs_state` matrix (parametrized; asserts `readme_exists`, `marker_present`, `docs_dir_exists`, `manifest_status`, `is_our_format`):
    - (a) empty repo;
    - (b) foreign README only;
    - (c) README with marker and no docs dir;
    - (d) docs dir with no manifest;
    - (e) docs dir with invalid manifest;
    - (f) marker plus valid manifest, which gives `is_our_format=True`;
    - (g) valid manifest with README missing;
    - (h) newer manifest.
29. `file_statuses` is empty unless the status is VALID. Keys are in sorted order.
30. A README with invalid UTF-8 bytes does not crash: `readme_exists=True` and the marker is still detected when it is present on line 1.
31. The DocsState dataclass is frozen: assignment raises `FrozenInstanceError`.

## 8. Open questions

1. **README in `files`:** this plan assumes yes (kind `"readme"`). If T1 or the breakdown prefers a separate top-level `readme` field, `file_status` and the semantic checks change accordingly.
2. **Marker version vs manifest version disagreement** (for example marker v2 and manifest v1, or marker vN > current with no manifest): DocsState exposes both raw values. T2 must decide. The proposal is marker > current → treat like NEWER (exit 3), and any other mismatch → RECREATE.
3. **`manifest.docs_dir` mismatch** is treated as INVALID, which leads to REFUSE unless `--force`. The alternative is VALID with a warning, if users rename docs dirs by hand.
4. **Empty docs dir:** should an existing but empty docs dir with no manifest still REFUSE? If T2 wants to allow it, add `docs_dir_empty: bool` to DocsState. It is cheap to compute here.
5. **Error classes:** does T1 want a `ManifestError`/`NewerFormatError` raised from a helper (for example `require_loadable(state)`), or is status-only reporting enough (the current plan)?
6. **`extra="forbid"` vs `"ignore"`** on the manifest models. Forbid is strict and requires a format bump for any new field. Ignore is more tolerant of patch-level tool versions.
7. **Case-sensitive marker:** a hand-lowercased or reformatted marker currently counts as foreign. Is that acceptable?
